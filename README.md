# Facebook / Threads 快速封鎖 0.4.3（Chrome）

在留言作者姓名旁點「封鎖此人」，加入佇列後依序向 Facebook 送出封鎖請求，不開新分頁、不操作個人檔案選單。這會真正封鎖帳號。

## Threads 支援

- 在貼文與回覆作者旁加入「封鎖此人」，與 Facebook 使用相同的分頁內佇列、2 秒間隔、暫停／繼續／取消操作。
- Threads 目前透過原生「更多 → 封鎖 → 確認」流程操作，並非直接 API。必須精確比對確認視窗中的帳號，再自動確認；只有明確成功提示才算完成。
- 以作者網址、同一作者的貼文時間連結與唯一選單共同辨識作者列，不在內文提及的帳號旁加按鈕。
- Threads 處理時請保留原分頁；操作其他按鈕、鍵盤或切換頁面會中斷。留言被移除、找不到選單、帳號不符或成功結果不明時暫停。
- 新增 Threads 網站內容腳本存取範圍（threads.com / threads.net）；不新增 cookies 或背景服務權限。沒有將資料傳送到第三方。
- 已檢查真實 Threads 貼文與回覆介面、原生確認視窗；本機模擬驗證完成與錯誤帳號攔截。已在使用者指定的真實 Threads 帳號完成一次封鎖，確認個人檔案顯示「解除封鎖」、佇列完成 1 人且失敗 0 次；直接 API 尚未驗證。

## 安裝與更新

1. Chrome 開啟 `chrome://extensions`，啟用開發人員模式。
2. 載入未封裝項目，選擇 `extension`。
3. 已安裝者按擴充功能的「重新載入」，再重新整理 Facebook。
4. 在 Facebook 分頁開啟擴充功能圖示，可查看「API 登入驗證已就緒」狀態。

公開版 ZIP 請先解壓縮，再選取直接包含 manifest.json 的資料夾。原始碼安裝則選取 extension 資料夾。

## 操作與結果

- 可連續點擊多位留言作者：先顯示「排隊中…」，每次只處理一人（包含查詢 ID），每筆結束後間隔 2 秒。這是本機節流設定，不代表 Facebook 保證接受的頻率。
- 左下角面板顯示等待、完成、失敗次數；可暫停、繼續或取消等待項目。取消不會撤回已送出的請求。
- 點面板的「收合」可縮成小按鈕，再點即可展開；收合不會停止封鎖，按鈕仍顯示剩餘人數或已暫停狀態。收合狀態保留至重新整理分頁。
- 任何失敗（含拒絕、限制、ID 解析失敗、逾時或結果不明）都暫停佇列。繼續僅處理剩餘項目，不自動重試失敗項目。結果不明時先查看封鎖名單。
- 佇列僅限目前分頁，不跨分頁協調或保存；請在同一分頁操作。重新整理、關閉分頁會清除等待項目，已送出的請求可能已完成。
- 執行前再次比對登入身分；若切換帳號則停止。

- 按下後顯示「封鎖中…」；只有收到 Facebook 的 `data.user_block.viewer` 成功回應、且沒有 API 錯誤，才顯示「已封鎖」。
- 同一分頁、相同帳號網址的留言同步更新。相同目標 ID 的同時請求會合併，成功後不會在該分頁再次送出。
- 不自動重試。網路中斷或逾時可能代表伺服器已完成但回應未到，請先查看 Facebook 封鎖名單。
- 數字 ID 直接使用；自訂網址會先背景讀取個人檔案，採用明確且一致的 profile metadata，或 JSON 中網址完全相符的 User 記錄 ID；不使用留言 ID、登入者 ID 或其他貼文作者的 ID。解析失敗即停止，不猜測 ID。
- 支援繁體中文留言與「甲回覆乙的留言」格式；英文只有基本相容處理，尚未在真實英文介面驗證。
- 匿名留言、特殊社團個人檔案網址、粉絲專頁身分或其他不支援情況會停止。

## API 與隱私

使用 2026-10-19 實際觀察到的 Facebook 網頁內部 GraphQL 操作 `ProfileCometActionBlockUserMutation`，不是官方公開 Graph API。操作文件 ID、驗證方式或回應格式變更時可能失效，需要更新程式。

Facebook 內容腳本在 `https://www.facebook.com/*` 運作；Threads 使用獨立的內容腳本。沒有額外 permissions、背景服務、cookies API、瀏覽紀錄、遠端程式或外部套件。從 Facebook 當前文件解析登入驗證資料，只傳回 Facebook 同源端點；僅於記憶體暫存，不持久儲存、不記錄，也不傳給開發者。沒有執行 Facebook 頁面提供的程式碼。

可在目標個人檔案開啟擴充功能，按「檢查目前個人檔案（不封鎖）」進行只讀辨識檢查。

## 驗證範圍

- 0.4.2：修正「甲回覆乙的回覆」辨識；測試涵蓋第 1–8 層巢狀、動態展開、重複作者與內文提及排除。

- 0.4.0：23 項單元測試通過；Chrome Threads 模擬頁驗證兩人依序封鎖，以及確認帳號不符時零送出並暫停。

- 0.3.0：20 項測試通過，含 30 人連續加入、序列與間隔、去重、失敗暫停不重試、取消、暫停與繼續。Chrome 本機模擬頁驗證上述操作，未大量封鎖真實帳號。

- 0.2.1 已在 Chrome 對 使用者提供的實際個人檔案完成背景只讀辨識；16 項自動測試通過。要求 HTML 回應並以 User 記錄的完整個人檔案網址配對。

- 已透過原生介面完成使用者指定帳號的一次實際封鎖，取得操作名稱、參數與成功回應（不包含登入驗證秘密）。
- 0.2.0 已載入使用者的 Chrome，確認真實 Facebook 留言按鈕更新、登入驗證資料可解析。
- 自動測試涵蓋驗證解析、目標 ID、錯誤回應、同時重複請求、成功去重、同源請求、自訂網址、拒絕自行封鎖及逾時不重試。
- Chrome 本機模擬測試驗證成功、API 拒絕、動態多層回覆與相同帳號按鈕同步。
- 尚未以 0.2.0 直接 API 封鎖另一個真實帳號；不把模擬測試當作真實 API 成功驗證。

## 開發

`npm test` 執行零套件依賴的 Node 測試。
`node tests/serve.cjs` 開啟僅限本機測試頁：

- `http://127.0.0.1:8765/tests/fixture.html`：模擬成功。
- `http://127.0.0.1:8765/tests/fixture.html?scenario=error`：模擬伺服器拒絕。

測試頁使用虛構帳號與替代 fetch，不傳送 Facebook 請求。ZIP 僅包含擴充功能與說明。
